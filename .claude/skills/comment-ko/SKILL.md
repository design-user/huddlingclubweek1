# comment-ko — 한국어 설명 주석 달기

사용자가 준 **코드 파일 하나**에 한국어 설명 주석을 추가한다. 사용자는 코딩 초보자다.

대상 파일: `$ARGUMENTS`

## 1. 시작 전 확인

- 경로가 없으면: 어떤 파일에 주석을 달지 묻고 멈춘다.
- 경로가 2개 이상이거나 폴더면: "한 번에 파일 하나만 처리해요. 어떤 파일부터 할까요?"라고 묻고 멈춘다.
- 파일이 없으면: 경로를 다시 확인해 달라고 하고 멈춘다.
- 주석을 쓸 수 없는 파일(`.json`, 이미지 등)이거나 `node_modules/`, `.next/` 안의 파일이면: 이유를 알리고 멈춘다.
- 파일을 처음부터 끝까지 읽고, 필요하면 이 파일이 불러오는(import) 다른 파일도 읽어서 역할을 정확히 파악한다. 모르는 Next.js 기능은 `node_modules/next/dist/docs/`에서 확인한다. **확실하지 않은 내용은 추측해서 주석에 쓰지 말고 사용자에게 묻는다.**

## 2. 주석 다는 규칙

### 넣을 것
- **파일 맨 위 요약**: 이 파일이 무슨 역할을 하는지 2~3줄. (`"use client"` 같은 지시문이 맨 위에 있어도 그 위에 주석을 둬도 된다.)
- **함수·컴포넌트·주요 블록 단위의 핵심 설명**: 이 부분이 *무엇을* 하고 *왜* 필요한지 한두 줄로.
- 전문 용어가 처음 나오면 한 줄로 풀어 쓴다. 예: `// props: 부모 컴포넌트가 넘겨주는 값`

### 넣지 않을 것
- 모든 줄마다 다는 주석 (핵심만 단다).
- `const a = 1 // a에 1을 넣는다`처럼 코드를 그대로 읽어 주는 주석.
- 확인하지 않은 추측.

### 지켜야 할 것
- **코드는 한 글자도 바꾸지 않는다.** 주석만 추가한다. 들여쓰기·줄바꿈·따옴표도 그대로 둔다.
- **기존 주석은 그대로 둔다.** 영어 주석도 지우거나 번역해서 바꾸지 않는다.
- 파일 종류에 맞는 주석 문법을 쓴다:
  - `.ts` `.tsx` `.js` `.mjs`: `//` 또는 `/* */`
  - JSX 안(태그 사이): `{/* 설명 */}`
  - `.css`: `/* 설명 */`
- 주석은 설명하는 코드 **바로 위 줄**에, 그 코드와 같은 들여쓰기로 단다.

## 3. 끝난 뒤 확인

1. `git diff <파일경로>`로 바뀐 부분이 **주석 추가뿐인지** 확인한다. 코드가 바뀐 줄이 있으면 되돌린다.
2. `npm run lint`를 실행한다. 실패하면 숨기지 말고 결과를 그대로 알린다.
3. `docs/작업기록.md` **맨 아래**에 AGENTS.md 형식으로 기록을 추가한다 (시간은 KST, `TZ=Asia/Seoul date "+%Y-%m-%d %H:%M"`으로 확인):

   ```markdown
   ## YYYY-MM-DD HH:MM — <파일경로> 한국어 주석 추가

   - **무엇을 바꿨는지:** <파일경로>에 한국어 설명 주석 추가 (코드 변경 없음)
   - **왜:** 코드를 이해하기 쉽게 하려고
   - **직접 확인하는 방법:** 에디터에서 <파일경로>를 열어 주석 확인
   ```

4. 사용자에게 쉬운 말로 알려준다:
   - 이 파일이 하는 일 한 줄 요약
   - 주석을 단 주요 부분 목록
   - 작업 중 확신이 없어 비워 둔 부분이 있으면 그 내용
